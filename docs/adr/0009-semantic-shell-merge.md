# ADR 0009: Baseline-Aware Semantic Shell Restore

**Status:** Accepted  
**Date:** 2026-09-04

## Context

Schema 4 captures both the user's desired Omarchy Shell document and the Omarchy baseline from capture time.

The initial restore behavior was intentionally conservative:

```text
target missing/default -> write captured shell.json
target customized differently -> refuse the whole Shell write
```

That protects unknown target work, but it is too coarse for cross-machine restoration. A laptop and desktop can each contain legitimate independent Shell customization.

## Decision

Blueprint will restore Shell state using a four-way semantic merge:

```text
A = captured Omarchy baseline
B = captured desired Shell state
C = current Omarchy baseline
T = current target Shell state
```

Portable source intent is `A -> B`; independent target customization is `C -> T`.

### Merge granularity

JSON objects merge recursively only when all four corresponding nodes are objects. Arrays, scalars, null, additions/deletions, and type changes are atomic merge units.

Bar layout is a focused exception after generic merge: uniquely identifiable
widget membership and placement are reconciled as one relationship across
`left`, `center`, and `right`. Captured additions, removals, and moves win over
target/default placement while target-only widgets remain. Duplicate IDs stay
conservatively conflict-managed; Blueprint never silently collapses ambiguous
target instances.

### Normal conflict policy

- Source-untouched target state is preserved and is not drift.
- Source changes apply when target remains at its current baseline.
- If target already equals source desired, no-op.
- If source and target changed the same unit differently, keep target and report conflict.
- Conflicts do not block unrelated safe changes.

### Force

`restore --force` resolves supported Shell conflicts in favor of captured source intent. It does not replace the whole target document and does not affect source-untouched target state.

Force never bypasses Shell schema compatibility, profile integrity, plugin provenance for newly enabled code, dependency failures, destination preconditions, backups, journaling, or atomic mutation behavior.

A write containing forced conflicts is high-risk.

### Status and verification

Shell status and verification become intent-based. A target satisfies the profile when every source-intended unit is satisfied. Target-only Shell customization is allowed.

A profile captured with no Shell customization has no Shell portable intent and therefore does not treat target customization as drift.

### Baseline evolution

If current Omarchy baseline C differs from captured baseline A, source-untouched fields keep current baseline/target values. Explicit source changes still apply when target remains unchanged from C.

### Generated merge output

Merged JSON is generated in memory and written through the generic atomic `FileWrite` executor. Generated bytes are not emitted in JSON dry-run plans. Raw destination hashes remain the mutation precondition.

### Plugin provenance

Only third-party plugin IDs newly introduced by the proposed merged result require source-profile provenance. Existing target-local plugin refs are preserved without being claimed by the source profile.

`check` still requires provenance for every third-party reference in the captured desired source document.

## Consequences

### Positive

- laptop-to-desktop restore works without deleting target Shell state;
- independent target customization survives normal and forced restore;
- new Omarchy defaults are not pinned accidentally when source never changed them;
- partial conflicts no longer block unrelated safe changes;
- unknown version-1 object fields can merge without a new Blueprint release;
- no schema migration or recapture is required.

### Negative

- arrays still conflict coarsely;
- generated merge output may reformat target JSON;
- normal restore can complete with unresolved conflicts and incomplete verification;
- the merge engine becomes a security-sensitive planning component.

## Supersedes

This ADR supersedes only ADR 0008's whole-document Shell restore conflict rule. ADR 0008's capture format, Shell ownership, plugin ownership handoff, provenance safety, backup, restart, and schema-4 decisions remain in force.

## Deferred

- widget-aware array merging;
- machine overlays;
- interactive conflict selection;
- generic structured merge framework;
- Hooks provider.
